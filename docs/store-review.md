# Google Play and App Store review

What the repository does so that the Android and iPhone apps pass store review, what must stay true when the code changes, and the facts the store forms ask for. Nothing here uploads anything to a store: the builds are made here, the upload and the forms are done by hand in Play Console and App Store Connect.

## In the code

| What | Where | Why |
| --- | --- | --- |
| Privacy policy at `https://www.polowanie.org/prywatnosc/`, linked from "Więcej", "O aplikacji" and every page footer | `landing/seo/privacy.ts`, `PRIVACY_URL` in `src/platform.ts` | Both stores require a public address and a link inside the app. |
| The Google Play build has no update check and no "Sprawdź aktualizację" button | `updatesItself()` in `src/platform.ts`, `VITE_DISTRIBUTION=play` | Play forbids an app from updating itself, or pointing at its own APK, outside Play. |
| App bundle (`.aab`) for Play | "Android app" workflow, **store: play** | Play accepts bundles, not APKs. |
| iOS privacy manifest | `ios/App/App/PrivacyInfo.xcprivacy` | App Store Connect refuses uploads that use UserDefaults (Capacitor) or file timestamps (Filesystem plugin) without a declared reason. |
| The iPhone app never names Android | `IOS` in `src/huntHelp.ts`, tested in `src/huntHelp.test.ts` | App Store guideline 2.3.10. |
| Background use is named before the location permission is asked | `shareConsentBackground` in `src/huntUi.ts` | Play's prominent-disclosure rule and App Store guideline 5.1.1. |
| "Not an official app" statement with the data sources | About page in `src/main.ts` | Play's rule for apps that show government information. |
| The grading service answers the iPhone app (`capacitor://localhost`) | `worker/wrangler.jsonc` | Without it AI grading fails in the iPhone app, and a reviewer sees a broken feature. |
| The app is for iPhone only (`TARGETED_DEVICE_FAMILY = 1`, no iPad orientations in `Info.plist`) | `ios/App/App.xcodeproj/project.pbxproj` | Nobody has tried the app on an iPad. A universal app is reviewed on an iPad and needs iPad screenshots. |
| The privacy policy names the controller | `CONTROLLER` in `landing/seo/privacy.ts` | GDPR article 13: a person has to know who holds their data. |
| Consent before the microphone and before an answer goes to the AI model | `consentMic`, `consentAi` in `src/oralUi.ts` | App Store guideline 5.1.2(i): name the third-party AI and ask first. |

## Keep true when the code changes

- A feature that sends or stores something new, or a new outside service: change `landing/seo/privacy.ts` (and its `UPDATED` date), the data table below, and the forms in both stores.
- A new permission or foreground service type in `AndroidManifest.xml`: Play Console needs a new declaration before the build is accepted.
- Text shown in the iPhone app must not name Android or Google Play. Text for the Play build must not offer an APK.
- `UIBackgroundModes` in `Info.plist` has `location` (sharing on a group hunt) and `processing` (saving maps). Do not add a mode no feature uses: each one is questioned in review.
- iPad: an iPhone-only app can become universal in a later version, but a released universal app cannot drop the iPad. Before setting `TARGETED_DEVICE_FAMILY` to `"1,2"`, test every screen on an iPad and prepare iPad screenshots. An iPhone-only app still opens on an iPad in a phone-sized window, and a reviewer may try it there.
- Version numbers only go up. Android: the workflow's version (code = major×10000 + minor×100 + patch). iOS: `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in Xcode; the build number must rise with every upload.

## Builds

**Google Play.** Actions → Android app → Run workflow → version (for example `1.2.0`) and **store: play**. The artifact `polowanie-play-aab` holds `polowanie-play.aab`, signed with the same key as the APKs; `polowanie-apk` is the same build as an APK for a last check on a phone. No GitHub release is made. In Play Console, when enrolling in Play App Signing, choose to use the existing key (the one in the repository secrets): then the fingerprint in `landing/public/.well-known/assetlinks.json` stays valid and the Play version installs over an APK from GitHub. With a key generated by Google, add its SHA-256 fingerprint to `assetlinks.json`.

**App Store.** On the Mac: `npm run ios:sync`, open Xcode (`npm run ios:open`), choose the paid team, set the version and build number, Product → Archive, then Distribute App → App Store Connect. Needs the paid Apple Developer Program and Xcode 26 or newer. Test through TestFlight first.

## Facts for the store forms

The same facts are in the privacy policy. Nothing is used for advertising or tracking, nothing is sold, and all traffic is encrypted (HTTPS).

| Data | When | Goes to | Linked to the person | Optional |
| --- | --- | --- | --- | --- |
| Precise location | Group hunt, after "Udostępniaj moją lokalizację", also in the background | Firebase (EU); seen by confirmed participants of that hunt | Yes (name + anonymous id) | Yes |
| Precise location | Weather for here | Open-Meteo, coordinates only | No | Yes |
| Name or nickname, role | Creating or joining a hunt | Firebase; seen by participants | Yes | Needed to join |
| Phone number | Only if typed in | Firebase; seen by confirmed participants | Yes | Yes |
| Anonymous user id | Group hunt, AI grading | Firebase; the grading service (as a daily fingerprint) | It is the id | No |
| Hunt content: sightings, shots, messages, alarm | During a hunt | Firebase; seen by participants | Yes | Yes |
| Text of an oral-exam answer | "Oceń z AI" | Cloudflare Worker → OpenAI or Anthropic; not stored | No | Yes |
| Voice | Microphone button | The phone's speech service (Apple, Google); the app keeps nothing | No | Yes |

Not collected: e-mail, contacts, photos, files, health data, payment data, advertising id, crash or usage statistics in the apps (Cloudflare Web Analytics runs only on the website).

Deletion: "Wypisz się" removes a participant's record, position and track; the leader's "Usuń polowanie" removes the hunt with everything in it; positions, tracks, sightings and shot locations are deleted 7 days after a hunt ends; anything else on request to kontakt@polowanie.org. There are no accounts, so the stores' account-deletion rules do not apply, but both forms ask how data is deleted: give the privacy policy address.

Permissions and why (Play declarations, App Review notes):

- Location, foreground service of type `location`: user-started location sharing with the other participants of a group hunt, with a permanent notification and a Stop button. The app does not ask for "all the time" location (`ACCESS_BACKGROUND_LOCATION` on Android, Always on iOS).
- Foreground service of type `dataSync`: saving map tiles the user chose for offline use, with a progress notification and a Stop button.
- Notifications: the two notifications above, the leader's messages and signals, the accident alarm. All made on the phone; no push service.
- Microphone and speech recognition: spoken answers in the oral exam, asked for at the first tap on the microphone button.

Reviewers cannot get past the club passphrase without help: creating a hunt and AI grading need it. Give them a passphrase (or a ready hunt with an invitation link), the steps to see location sharing in the background, and a short screen recording.
